## 1. y39_rank re-scans the whole archive, twice per section  (small effort)

`y39_rank.ps1:21` reads every farm in `over66.csv`; `:27` runs `afk_rescan.exe` over all of them.
It is called twice a section - `heat\compartment_finish.ps1:23` and `heat\second_pass.ps1:57`.

- Cost now: 0.0103 s/farm x 6,537 farms = 67 s per call, 134-227 s per section, single-threaded with
  15 cores and the GPU 100% idle.
- Change: cache the per-farm `afk_rescan` result keyed by seed+x+z; scan only farms absent from the cache
  (~1,000 from the compartment, ~150 from the second pass). Drop the `Add-Member` reflection in the
  rank loop at `:40` (rebuild rows as plain objects). Optionally thread `afk_rescan`'s per-farm loop,
  order-preserved.
- Identity: `afk_rescan` is a pure function of (seed, x, z, --dy, --window). Same inputs, same output;
  the cache key includes the flags. Row order and ranking are recomputed from the full set as now.
- Saving: 134-227 s -> ~12-25 s. **~135-210 s/section**, and it stops growing - at 20,000 farms the
  current code costs ~410 s/section, the cached version still ~12 s.
- Verify: run `y39_rank.ps1 -Top 0` before and after on the current archive, diff `y39_all.csv` byte for byte.

## 2. ArchiveResult re-reads index.csv for every filed farm  (medium effort)

`hunt_pipeline.ps1:452-460`, per filed farm: a `Select-String` over `index.csv` (`:453`), a second
`Select-String` (`:459`), and a full `Import-Csv` of `index.csv` (`:460`) whenever the cq matches.

- Cost now: 0.38 s + 3 x 0.012 s per farm; at 4.42 farms/spot that is ~1.8 s/spot. Measured 3.31 s/farm at
  65k index rows = 14.6 s/spot, i.e. 3.5x the GPU cost - an O(spots^2) term.
- Change: build the dup index once per filing process into a hashtable keyed by `seed,x,z` and by cq,
  update it in memory as farms are filed, and append to the CSVs without re-reading.
- Identity: the dup test is exact-match on the same keys the `Select-String` patterns use; an in-memory
  index built from the same file answers identically as long as every append also updates it.
- Saving: filing 4.77 -> ~2.9 s/spot, which drops it below the 4.21 s GPU wait, so the filing queue stops
  growing: the 157 s Test-Cut drain stall and the ~120 s final drain both disappear.
  **~280-330 s/section (11-12%)**, growing with the archive.
- Verify: re-file a saved compartment's farms into a copy of the records tree, diff `index.csv`,
  `over66.csv` and `y39_all.csv` against the originals.
